# 0002. Rebuild on Next.js App Router with TypeScript

- **Status:** Accepted. The Cache Components part is superseded by [0009](./0009-static-export-for-github-pages.md)
- **Date:** 2026-10-19
- **Story:** APW-001

## Context

The legacy site was a Create React App (CRA) single-page app. CRA is deprecated, renders
everything in the browser (an empty HTML shell for search engines), and the code was untyped. The
site is a marketing site whose content changes rarely, where SEO and first-load speed matter most.

## Decision

Rebuild with **Next.js 16 (App Router)**, **React 19** and **TypeScript in `strict` mode** (plus
`noUncheckedIndexedAccess`), keeping the defaults generated by `create-next-app@16.4.2`:
Turbopack, Cache Components and Partial Prefetching. Pages are Server Components, prerendered at
build time; only interactive leaves are Client Components.

## Consequences

- Full HTML at first byte: better SEO, social previews and performance. Lighthouse SEO is 100.
- Built-in image optimisation, font self-hosting and metadata APIs replace custom code.
- Cache Components forbids non-deterministic values (such as `new Date()`) during prerender; the
  footer year therefore uses `"use cache"` with `cacheLife("days")`.
- Next.js 16 changed several APIs (`next lint` removed, `priority` → `preload`, error boundaries
  receive `retry`). Contributors must read the version-matched docs in
  `node_modules/next/dist/docs/` (see `AGENTS.md`).

## Alternatives considered

| Option                   | Why not                                                                                                                                               |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep CRA                 | Deprecated, client-only rendering, poor SEO                                                                                                           |
| Vite + React SPA         | Still client-rendered; would need a separate prerendering step                                                                                        |
| Astro / static generator | Good fit for static content, but the brief asked for Next.js, and Next.js leaves room for future server features (enquiry form APW-050, i18n APW-051) |
